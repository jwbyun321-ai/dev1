# FLEX — 나의 업무기록

업무 날짜, 제목, 프로젝트, 내용, 상태를 등록하고 검색·수정·삭제·복원합니다. CSV는 현재 필터로 조회 중인 기록을 내보냅니다. 삭제는 휴지통 이동이며 영구 삭제 기능은 제공하지 않습니다.

## 현재 서비스

- 공개 주소: https://jwbyun321-ai.github.io/dev1/
- Supabase 프로젝트: `flex-work-journal` (`huibfpypunawsoficiil`), 서울 리전
- 저장 테이블: `public.work_logs`
- 이메일 로그인 링크를 받은 뒤 본인 기록을 저장·조회합니다.
- 2026-10-16 데이터베이스 검증: 본인 기록 등록·조회·수정·휴지통 이동·복원, 타 사용자 조회·수정·등록 차단, 익명 사용자 접근 차단 통과. 테스트 데이터는 트랜잭션 롤백으로 정리했습니다. 실제 이메일 수신 및 사용자 로그인 확인은 첫 사용 시 필요합니다.
- Supabase 보안 점검 도구에서 지적된 항목은 없었습니다.
- Supabase JavaScript SDK는 `2.118.0` CDN 번들로 버전을 고정했습니다.

## 저장 방식

- `config.js` 값이 비어 있으면 **브라우저 저장 모드**입니다. 데이터는 현재 브라우저에만 저장되고 기기 간 동기화되지 않습니다. 브라우저 데이터를 지우면 기록도 사라집니다.
- Supabase를 연결하면 이메일 링크 로그인 후 본인 기록을 데이터베이스에 저장합니다. 클라우드 연결 실패 시 브라우저 저장으로 조용히 전환하지 않습니다.
- 기존 브라우저 기록을 클라우드로 자동 전송하지 않습니다. 전환 전 필요한 기록은 CSV로 내보내세요.

## Supabase 연결

1. Supabase 프로젝트에서 `schema.sql`을 SQL Editor로 실행합니다. 이 스크립트는 새 테이블용이며 중복 실행하지 않습니다.
2. Authentication의 URL Configuration에 Site URL `https://jwbyun321-ai.github.io/dev1/`과 같은 Redirect URL을 등록합니다. 로컬 테스트용으로 `http://localhost:4173/`도 Redirect URL에 추가합니다.
3. 이메일 인증을 활성화하고 사용자 가입 허용 여부를 설정합니다. 앱은 이메일 로그인 링크를 사용하며 이메일 확인 전 데이터를 조회할 수 없습니다.
4. 프로젝트 URL과 **publishable key** (또는 legacy **anon key**)를 `config.js`에 입력합니다. **secret key와 service_role 키는 넣지 마세요.**
5. `index.html`, `worklog.css`, `worklog.js`, `config.js`, `.nojekyll`을 GitHub 저장소 루트에 업로드합니다.
6. 서로 다른 계정으로 로그인해 상대 계정의 기록이 조회·변경되지 않는지 확인합니다. 이 확인은 실제 프로젝트 연결 후 수행해야 합니다.

테이블에는 사용자별 RLS 정책이 적용되며 익명 사용자의 테이블 접근은 허용하지 않습니다. 페이지 자체와 클라이언트 설정은 공개됩니다. 클라우드 기록은 새로고침 버튼으로 다시 조회합니다.

## 개발 파일

`node server.mjs`로 로컬 서버를 시작합니다. 외부 패키지 설치는 필요하지 않습니다. 클라우드 연결 시 Supabase JavaScript SDK를 공식 문서의 CDN 주소에서 불러옵니다.

이전 반응형 테스트 화면은 `responsive.html`에 보존했습니다. 아래는 이전 페이지 테스트 안내입니다.

설치나 빌드 없이 동작하는 HTML·CSS·JavaScript 웹사이트입니다.

## 미리보기

`index.html`을 브라우저에서 열면 됩니다. 로컬 서버를 사용하려면 Node.js가 설치된 환경에서 `node server.mjs`를 실행하고 http://localhost:4173 을 여세요.

## 테스트하기

- 640px 미만: 모바일, 카드 1열, 접이식 메뉴
- 640px 이상 ~ 1024px 미만: 태블릿, 카드 2열 (마지막 카드는 전체 너비)
- 1024px 이상: 데스크톱, 카드 3열
- 화면 너비가 실시간으로 표시됩니다. 메뉴와 테마 전환 버튼도 눌러보세요.
- 테마 선택은 브라우저에 저장됩니다. 최초 방문은 시스템 테마를 따릅니다.

## GitHub Pages에 올리기

1. GitHub에서 저장소를 만들고 이 폴더의 파일을 업로드합니다.
2. 저장소의 **Settings → Pages**에서 **Deploy from a branch**를 선택합니다.
3. 업로드한 브랜치(일반적으로 `main`)와 **/ (root)**를 선택하고 저장합니다.
4. 배포 후 GitHub가 표시하는 주소로 접속합니다.

경로를 상대 경로로 작성해 저장소 하위 주소에서도 동작합니다. 별도 API 키나 서버는 필요하지 않습니다. 글꼴은 Google Fonts에서 불러오며, 연결되지 않으면 시스템 글꼴을 사용합니다.

## 파일

- `index.html`: 화면 내용
- `style.css`: 디자인과 반응형 규칙
- `script.js`: 화면 정보, 메뉴, 테마 전환
- `server.mjs`: 로컬 미리보기용 서버 (배포에는 필요 없음)
